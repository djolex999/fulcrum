# Fulcrum Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An MCP server that sits between an AI agent and Adapty, judges A/B tests on their declared goal with a calibrated group-sequential boundary, and executes a test stop only after human approval.

**Architecture:** One Node process: the MCP server (stdio, for Claude Code) and a Hono approval page on 127.0.0.1 share an in-memory gate and a JSONL audit ledger. Stats read the offline CSV in place; reads and the stop go through a typed wrapper around the Adapty CLI, which alone sees `ADAPTY_TOKEN`.

**Tech Stack:** TypeScript (strict), Node 22, ESM, Vitest, `@modelcontextprotocol/sdk`, `zod`, `hono`, `@hono/node-server`, `tsx`.

**Spec:** [SPEC.md](../../../SPEC.md) (contracts, ACs) and [the demo design](../specs/2026-11-07-fulcrum-demo-design.md). Read both.

## Global Constraints

- TypeScript strict, no `any`, ESM, Node 22, named exports, no barrel `index.ts`.
- **Ask Djordje before installing packages.** Runtime: `@modelcontextprotocol/sdk` (MCP server), `zod` (tool schemas), `hono` + `@hono/node-server` (approval page). Dev: `typescript`, `vitest`, `tsx`, `@types/node`. Nothing else without asking.
- App id `f8711513-c780-42b2-b6da-6c44094f3867`. CLI 0.18.0, always `--json`; `stop` needs `-y` with `--json`.
- `ADAPTY_TOKEN` and `ANTHROPIC_API_KEY` only from `.env` (Fulcrum loads it with `process.loadEnvFile`). The token goes to the CLI through the child env only, never in args, output, errors, ledger or logs.
- Offline data: `OFFLINE_DATA_DIR` (default `~/Projects/adapty-seed-data-hack/data/offline`), read in place, never copied. Test fixtures are tiny synthetic files generated in the test, not excerpts of the dataset.
- Tests that write to Adapty run only when `ALLOW_WRITES=1` is set by a human. Never set it in scripts or config.
- Never stop Onboarding or Main except in the live demo, by Djordje.
- Every number returned carries `source: "export_csv" | "adapty_metrics"`.
- Test names start with their AC id (for example `AC-4 approved action calls the CLI once`).
- Commit after each task that passes `npm run typecheck && npm test`. Push only when Djordje asks.
- After each phase: run `phase-checkpoint`. Before key commits (end of tasks 3, 8, 9): a fresh reviewer subagent on Fable that sees only the diff and SPEC.md answers "can the agent bypass the gate, can the token leak, is the boundary right"; log it in AI_LOG.md.

## Review Focus

1. **Double approval** (two clicks, two tabs) of one action: the CLI runs once; the second click gets "already executed". Test in Task 3.
2. **The CLI fails during the stop** (non-zero exit or non-JSON output): the action becomes `failed` with a redacted reason, a ledger entry is written, and nothing retries automatically. Test in Task 3.
3. **A test in `test-plans.json` that Adapty does not list** (renamed or archived): `UNKNOWN_TEST` with the title, not a crash. Test in Task 8.
4. **`as_of` before the first install or after the data end:** `INVALID_AS_OF` with the valid range. Test in Task 8.
5. **An approval with an empty name, or from a non-local address:** refused. The page binds to 127.0.0.1 only. Test in Task 10.
